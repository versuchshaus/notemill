# Developing Notemill

Everything a contributor needs: how the code is laid out, how to run it from source, how the
Notion sign-in works, how to test, and how a release is made. If you only want to *use*
Notemill, the [README](README.md) is all you need.

## Layout

| Path | What it is |
| --- | --- |
| `manifest.base.json` | The manifest template. `manifest.json` is generated from it (see below). |
| `readability.js` | Arc90's Readability parser plus everything Notemill added: the reading view, the tools bar, Markdown and Notion conversion. Injected on click. |
| `content.js` | Runs the parser once per page. |
| `sw.js` | The service worker: injects the reader, talks to Notion, writes downloads and folders. |
| `notion.js` | Notion sign-in, destinations, tags and page creation. |
| `folder.js`, `pick.html`, `pick.js` | The remembered save folder (File System Access) and the small window that picks it. |
| `options.html`, `options.js`, `ui-theme.js` | The settings page and the shared light/dark switch. |
| `css/` | `readability.css` (reader and bar), `ui-tokens.css` (shared colour tokens), `extension.css` (settings and picker), bundled fonts. |
| `img/` | Icons, drawn by `tools/icons.py`. |
| `server/` | The Notion token exchange, a Cloudflare Worker. Deployed separately. |
| `tools/` | Build and maintenance scripts. |
| `tests/` | Unit tests and isolated-browser checks. |
| `assets/readme/` | README pictures, generated by `tools/screenshots.cjs`. |

## Run from source

```sh
make manifest        # writes manifest.json from manifest.base.json
```

Then load the repository folder itself with **Load unpacked** on `chrome://extensions`.
After editing, click the reload arrow on the Notemill card, then reload the article tab.

**Extension id.** An unpacked extension's id normally follows its folder path. If you have
the project's signing key, `tools/manifest.py` pins the id by adding the matching public key
to `manifest.json`; it looks for the key in `$NOTEMILL_KEY`,
`~/Library/Application Support/Notemill/notemill-key.pem` and `~/.config/notemill/`. The key
never goes into the repository. Without it the id follows the folder, which is fine for
development but means you need your own Notion app (next section).

## The Notion app

Notion's token endpoint requires `client_id:client_secret` and supports no PKCE, so a sign-in
needs a confidential client. Copy `notion-config.example.js` to `notion-config.js`
(gitignored) and choose one of:

- **Your own integration.** Create a *public* integration at
  [notion.so/profile/integrations](https://www.notion.so/profile/integrations), register the
  redirect URI the settings page prints (`https://<extension-id>.chromiumapp.org/notion`),
  and put its client id and secret into `notion-config.js` or into the settings page under
  *Notion app credentials*. Fine for a personal copy; never distribute a build containing it.
- **The token exchange.** Deploy [`server/`](server/README.md), put its URL in `exchangeUrl`
  and leave `clientSecret` empty. This is what every distributed build does.

## Build targets

| Command | Output | Use |
| --- | --- | --- |
| `make release` | `notemill-<version>.zip` and `notemill.zip` | **The download for testers.** Pinned id, public client id and exchange URL, no secret. Refuses to build without the pinned id. |
| `make` | `notemill-<version>-local.zip` | Your own build. It packs your local `notion-config.js`, which may hold your secret: never share it. |
| `make store` | `notemill-<version>-store.zip` | A Chrome Web Store submission: no pinned key (the store assigns the id), no secret. |
| `make firefox` | `notemill-<version>-firefox.zip` | Experimental Firefox build (event page instead of service worker). Untested. |
| `make icons` | `img/icon-*.png` | Redraws the icons. |
| `make clean` | | Removes `build/` and every archive. |

## Tests

Unit tests, no browser needed:

```sh
node --test tests/*.test.cjs
```

The browser checks drive a separate headless Chrome over the DevTools protocol, on port 9563
(`CDP_URL` overrides it). Always use a throwaway profile, never your own:

```sh
profile=$(mktemp -d)
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new \
  --enable-automation --enable-unsafe-extension-debugging \
  --user-data-dir="$profile" --remote-debugging-port=9563 \
  --no-first-run --no-default-browser-check about:blank &
node tests/browser-toolbar.cjs      # reader and toolbar, extension services mocked
node tests/browser-surfaces.cjs     # settings page and folder picker, mocked
node tests/browser-extension.cjs    # the real extension: install, action, storage, downloads
kill %1
```

`browser-extension.cjs` also expects downloads to go to a folder inside the profile without a
prompt: before starting Chrome, write `{"download": {"default_directory": "<profile>/downloads",
"prompt_for_download": false}}` to `<profile>/Default/Preferences`.

Not covered by automated tests: the native folder dialog, a real Notion sign-in and page
write, the system clipboard and printing.

## Pictures

```sh
make release && node tools/screenshots.cjs   # README pictures, light and dark
python3 tools/barpreview.py                  # every toolbar state, into build/preview/
```

`tools/screenshots.cjs` runs its own headless Chrome with a throwaway profile, mocks Notion
with a fictional workspace, uses the sample article in `tools/fixture/`, and loads the release
build into Chrome's extensions page for the install picture. Nothing personal can appear in
the pictures.

## Making a release

1. Raise `version` in `manifest.base.json`.
2. `make release`.
3. Test `notemill.zip` the way a tester would: a fresh browser profile, *Load unpacked*,
   *Connect to Notion*, send one article, save one as Markdown.
4. Publish:

   ```sh
   gh release create v<version> notemill.zip --title "Notemill <version>" --notes "…"
   ```

   The asset must be named `notemill.zip`: the README links to
   `releases/latest/download/notemill.zip`, which always points at the newest release.

## Where it came from

The article parser is Arc90's Readability 1.7.1, used under the **Apache License 2.0**; the
header of `readability.js` lists every change made to it. *Readability* is a trademark of
Arc90 Inc, which is why the product has its own name.

Notemill began as a fork of LReadability by luxcem (GPLv3). **No code from it remains**: the
stylesheet, settings, injection script, build scripts and icons were rewritten from scratch,
and the icons are original work drawn by `tools/icons.py`.

What this fork added: Manifest V3 with the parser injected on click (no host permissions to
read a page), parser fixes that keep article images and whole articles, Markdown export to
the clipboard or a folder with images, export to Notion through the official API with tags,
light and dark themes, a sticky tools bar and full keyboard operation.
